# Термоконтур / Termokontur

**Локальная система мониторинга температуры помещений** для школ, детских садов, офисов и других зданий. Бесплатная, открытая, без облачной зависимости для веб-панели. Ручной ввод, MAX-бот и датчики через Home Assistant используют одну базу измерений.

> **Версия 0.1.0 — MVP.** Панель и приём показаний готовы для пробного развёртывания. Интеграция MAX через Long Polling предназначена **только для тестирования** согласно документации MAX; для постоянной эксплуатации необходим переход на Webhook с доверенным HTTPS. Напоминания по расписанию, несколько ролей, полноценные нормативные отчёты и управление датчиками Zigbee пока не реализованы.

## Возможности

- Учёт корпусов, этажей, кабинетов, типов помещений и индивидуальных температурных диапазонов.
- Панель со статусами «в норме», «ниже», «выше», «нет свежих данных». По умолчанию показание считается устаревшим через 26 часов.
- Отдельный контроль сбора показаний **за местный календарный день**: количество кабинетов с измерениями и список пропусков.
- Опциональные напоминания учителям через MAX в заданное время по будням, один раз на сотрудника за день.
- Журнал и график измерений; ручной ввод администратором, экспорт CSV для Excel.
- MAX: одноразовая привязка учителя к кабинету; ввод температуры сообщением.
- Home Assistant: входящий API с отдельным ключом, идемпотентность по `event_id`.
- Вход администратора по паролю, cookie с подписью, проверка источника запросов; отсутствие незаданных паролей по умолчанию.
- SQLite в WAL-режиме. Данные сохраняются после перезагрузки.
- **Установка без Docker** через systemd в Debian 12/13 LXC Proxmox; Docker Compose для желающих.

## Быстрый запуск в Proxmox LXC (без Docker)

Рекомендуемый контейнер: Debian 13, 1 vCPU, 512 МБ–1 ГБ RAM, диск от 4 ГБ, статический IP в школьной сети. Белый IP не требуется.

Внутри контейнера от `root`:

```bash
apt update && apt install -y git ca-certificates
git clone https://github.com/TeenKode/Termokontur.git
cd Termokontur
bash scripts/install-debian.sh
```

Установщик создаёт пользователя `termokontur`, Python venv, настройки в `/etc/termokontur/termokontur.env`, базу в `/var/lib/termokontur/` и службу systemd. При **первой** установке генерирует случайный пароль администратора и печатает его **один раз** в терминал. Сохраните пароль.

Откройте `http://IP-КОНТЕЙНЕРА:8092/` из локальной сети.

```bash
systemctl status termokontur --no-pager
journalctl -u termokontur -n 100 --no-pager
systemctl restart termokontur
```

Повторный запуск установщика сохраняет существующие секреты и базу. Для обновления: `git pull`, затем `sudo bash scripts/install-debian.sh`.

> На локальном HTTP передача пароля не шифруется. Разрешайте доступ только из доверенной школьной сети. Для доступа извне используйте VPN или обратный HTTPS-прокси с доверенным сертификатом. Не публикуйте порт 8092 напрямую в интернет. Для HTTPS установите `TERMOKONTUR_SECURE_COOKIE=1` в конфигурации и перезапустите службу.

## Установка Docker Compose (альтернативная)

```bash
cp .env.example .env
# Замените ВСЕ REPLACE_WITH_... на длинные случайные секреты.
docker compose up -d --build
```

Панель: `http://localhost:8092/`. Данные в volume `app-data`. Для MAX (только тестирование): настройте `MAX_BOT_TOKEN` и запустите `docker compose --profile max up -d --build`.


## Администрирование через веб-панель (после обновления)

### Упрощённый пароль администратора

Пароль администратора теперь может содержать **от 8 до 256 символов**. Требований к обязательным спецсимволам, цифрам или регистру нет: допустимы, например, 8 обычных цифр или букв. Более длинный пароль безопаснее, особенно если панель доступна не только в локальной сети. При смене пароля введённые символы можно показать или скрыть, а совпадение двух новых паролей проверяется сразу при вводе.

### Дополнительные функции кабинетов

В разделе **Помещения** появился поиск по корпусу, этажу, названию и типу, а также функции **Копировать** (заполнить форму параметрами существующего кабинета), **Показать отключённые** и **Восстановить** без потери прежней истории. Реестр кабинетов можно выгрузить в CSV для Excel, включая отключённые помещения.


Раздел **Настройки** позволяет без консоли менять название организации, часовой пояс, период устаревания показаний, расписание напоминаний, токен MAX и пароль администратора. Токен и ключ датчиков не отображаются повторно после сохранения. Ключ Home Assistant можно заменить кнопкой (новый показывается один раз — заранее сохраните его в HA). Все пользовательские настройки хранятся в SQLite. Внутренний секрет подписи сессий `TERMOKONTUR_SECRET` остаётся системным параметром установки, а не настройкой пользователя.

При первой установке пароль генерируется установщиком. При запуске приложения он переносится в базу как хеш PBKDF2. После смены пароля старый пароль из файла первоначальной установки больше не принимается, а все прежние сессии прекращаются. При первом запуске новой версии на существующей базе прежние параметры из `.env` импортируются **однократно**; изменения через веб-панель после этого не перезаписываются значениями из файла.

### Быстрое добавление кабинетов

В разделе **Помещения** нажмите **Добавить списком**. Укажите корпус, этаж, тип, нормативы и список. Поддерживаются номера через запятую, строки из Excel, диапазоны вроде `101-125` и собственные названия. Перед отправкой показывается предварительный просмотр. До 250 кабинетов за операцию, уже существующие пропускаются без удаления истории. Если номер выглядит как `101`, к нему добавляется указанный префикс, например `Кабинет `.

### Автообновление в Debian / Proxmox LXC без Docker

После установки новой версии через `bash scripts/install-debian.sh` появится раздел **Настройки → Обновление**. Это одноразовый этап перехода для уже установленных ранних версий, у которых ещё нет системной службы обновлений. Далее действия выполняются в панели:

1. Нажмите **Проверить обновления** (через GitHub API).
2. Если новая версия доступна, нажмите **Установить обновление**.
3. Система создаёт запрос, который выполняет отдельная системная служба `termokontur-update.service`.
4. Обновитель загружает только `main` из `TeenKode/Termokontur`, создаёт новое виртуальное окружение Python, проверяет запуск и переключает версию.
5. При неудаче запуска веб-службы выполняется попытка отката на предыдущие файлы.

Сервер **не исполняет команды пользователя через HTTP**, веб-служба работает без root. Данные SQLite и секреты не входят в каталог обновляемого приложения и не заменяются. Файлы новой версии нельзя изменять через веб-службу. Отчёты об ошибках установки доступны в `journalctl -u termokontur-update.service`. Для проверки текущего хода процесса возвращайтесь в раздел обновлений после перезапуска панели. Для установки обновлений серверу нужен доступ в интернет к GitHub и PyPI.

**Docker Compose:** автоматическая замена образов в панели не поддерживается. Обновляйте командой `git pull && docker compose up -d --build` на хосте. При этом данные в именованном Docker volume сохраняются.

**Важно:** автообновление с публичного GitHub — доверие к обновлениям автора репозитория. Для критической инфраструктуры используйте резервные копии перед обновлениями и контролируйте выпуск новых версий. SQLite сохраняется при обновлении, но возможные будущие миграции БД могут потребовать отдельного отката из резервной копии.

### Испытание без раскрытия наружу

В первую очередь проверьте 2–3 кабинета, ручной замер, вход/смену пароля, импорт списка, напоминания MAX и передачу данных от Home Assistant. На новой установке автоматические напоминания выключены. Сервер LXC можно оставлять только в школьной LAN.

## Начало работы

1. Войдите в панель под сгенерированным паролем и затем смените его в разделе «Настройки». 
2. Откройте **Помещения**, добавьте корпус и кабинеты. Диапазоны по умолчанию 18–24 °C — пример для настройки, **не универсальный норматив**. Установите диапазоны по действующим требованиям для каждого типа помещения.
3. В разделе **Измерения** занесите первые показания.
4. Для MAX нажмите **Код MAX** у кабинета и передайте одноразовый код учителю. Для датчиков используйте API `POST /api/ingest`.

## Массовая выгрузка кодов подключения MAX

В разделе **Помещения → Коды подключения MAX** администратор может выпустить коды сразу для нескольких кабинетов и скачать CSV для Excel:

1. Выберите корпус, при необходимости отфильтруйте помещения по названию или этажу.
2. Отметьте нужные кабинеты или выберите все отображённые (не более **250 за один раз**).
3. Задайте срок действия: **30 минут, 2 часа, 24 часа (по умолчанию) или 7 дней**.
4. Нажмите **Создать и скачать CSV**. Файл содержит корпус, этаж, кабинет, ID, отдельный одноразовый код, готовую команду `/bind КОД`, время окончания действия (UTC) и пустую колонку для ответственного сотрудника.
5. Передайте **каждому учителю только его код**. Учитель вводит команду `/bind КОД` в личном диалоге с MAX-ботом.

Коды нельзя повторно просмотреть или скачать из системы: в SQLite сохраняются только SHA-256-хеши. **При повторном выпуске новые коды аннулируют ранее неиспользованные коды выбранных кабинетов.** После первого успешного использования код становится недействительным. История измерений и уже выполненные привязки не затрагиваются.

CSV содержит секреты подключения, поэтому не публикуйте его в общих чатах, не храните в открытых общих папках. При утере файла заново сгенерируйте коды для нужных кабинетов. Для массовой раздачи используйте минимальный подходящий срок действия.

## MAX в производственном режиме: HTTPS webhook

В разделе **Настройки → Интеграции MAX и Home Assistant → MAX: способ получения сообщений** можно указать публичный адрес вида `https://monitor.example.org/api/max/webhook` и включить webhook прямо из веб-панели. Сервер автоматически регистрирует подписку через `POST /subscriptions` в MAX с индивидуальным секретом `X-Max-Bot-Api-Secret`. Секрет хранится в SQLite и никогда не показывается в API настроек. Если регистрация MAX не удалась, режим не изменится.

**Для Proxmox LXC за NAT:** организуйте выходящий HTTPS-туннель через сторонний сервис или отдельный VPS с доверенным сертификатом. Публичным должен стать **только путь** `/api/max/webhook` — веб-панель оставьте в LAN или VPN. MAX принимает webhook только по HTTPS на порту 443 и доверенном сертификате. Локальный прокси должен передавать исходный заголовок `X-Max-Bot-Api-Secret` без изменений.

В режиме webhook работает служба `termokontur-max` — она **не опрашивает /updates**, а доставляет подтверждения из устойчивой очереди SQLite и отправляет запланированные напоминания. В docker compose для этого обязательно запустите профиль `max`:
```bash
docker compose --profile max up -d --build
```

В разделе настроек есть кнопка **«Тестовый Long Polling»**, которая сначала удаляет webhook-подписку из MAX, затем переводит приложение обратно в экспериментальный режим опроса. Production-режимы одновременно не включаются.

События сначала записываются в SQLite и затем подтверждаются MAX. Ответы пользователям сохраняются в очереди и повторяются при временной сетевой ошибке; заодно одно и то же входящее событие не исполняется повторно при ошибке отправки ответа. Исходящие сообщения имеют семантику *at least once*: при сетевом таймауте уже доставленный ответ иногда может продублироваться, но команда не должна исполниться повторно.

Официальная документация: [Подписка webhook](https://dev.max.ru/docs-api/methods/POST/subscriptions/), [Уведомления MAX](https://dev.max.ru/docs-api/use-cases/event-notifications/).

## MAX без публичного IP (экспериментально)

1. Создайте MAX-бота в доступном вам аккаунте MAX для бизнеса (при необходимости требуется верификация организации), получите токен.
2. Откройте конфигурацию: `sudo nano /etc/termokontur/termokontur.env`.
3. Укажите `MAX_BOT_TOKEN=...` — храните токен в секрете.
4. Запустите `sudo systemctl enable --now termokontur-max`.
5. Проверьте `journalctl -u termokontur-max -f`.

**Команды учителя:** `/bind КОД`, `/rooms`, `/today`, `/temp 21,5` (один кабинет), `/temp 3 21,5` (несколько кабинетов, где 3 — ID), `/unbind 3`, `/help`. Можно отправить просто `21,5`, если кабинет один. Одноразовый код действует 30 минут. Бот принимает данные **только в личном диалоге** и только для привязанных кабинетов.

### Ежедневные напоминания учителям

В новой версии для пилотного запуска автонапоминания включаются из **Настройки → Общие параметры**. Старые параметры в `/etc/termokontur/termokontur.env` импортируются только при первом запуске после обновления. Пример значений старой версии:

```ini
TERMOKONTUR_TZ=Asia/Vladivostok
TERMOKONTUR_REMINDERS_ENABLED=1
TERMOKONTUR_REMINDER_TIME=09:00
TERMOKONTUR_REMINDER_DAYS=0,1,2,3,4
TERMOKONTUR_REMINDER_WINDOW_MINUTES=120
```

Изменения, внесённые в панели, действуют без перезапуска. Часовой пояс по умолчанию — UTC; для Хабаровского края используйте `Asia/Vladivostok`. Цифры дней недели: 0 — понедельник, 6 — воскресенье. Напоминания **отключены по умолчанию**. Они отправляются только после указанного времени и в течение заданного окна, только сотрудникам с привязанными кабинетами **без показаний за текущий местный день**. Если один пользователь привязан к нескольким помещениям, ему приходит одно сообщение со списком пропусков. Запись отправки сохраняется в SQLite: перезагрузка службы обычно не создаёт повторное сообщение. При падении в момент отправки возможен дубль; предусмотрено не более трёх попыток с интервалом от пяти минут.

Система пока не умеет автоматически пропускать праздничные дни и каникулы; перед ними отключайте напоминания в конфигурации.

Связь с MAX — исходящие HTTPS-запросы сервера, поэтому белый IP и проброс портов не требуются. В API MAX необходимо использовать `https://platform-api2.max.ru` и заголовок `Authorization: <bot_token>`. Обновления сохраняют `marker` в SQLite; повторные события не создают дубликатов измерений. **MAX прямо обозначает Long Polling как неподходящий для production**. Для постоянной эксплуатации запланирован Webhook через туннель и публичный доверенный HTTPS, совместимость маршрута нужно проверить отдельно.

Официальные источники: [GET /updates](https://dev.max.ru/docs-api/methods/GET/updates), [POST /messages](https://dev.max.ru/docs-api/methods/POST/messages).

## Home Assistant

В веб-панели узнайте ID нужного помещения. Ключ датчиков автоматически генерируется при установке без Docker и находится в файле `/etc/termokontur/termokontur.env` под именем `TERMOKONTUR_INGEST_KEY`.

Пробный запрос из доверенной сети:

```bash
curl -X POST http://127.0.0.1:8092/api/ingest \
  -H "Content-Type: application/json" \
  -H "X-Api-Key: ВАШ_КЛЮЧ" \
  -d '{"room_id":1,"value":21.8,"device":"sensor.class_101"}'
```

**Важно:** выполняйте эту команду внутри контейнера или замените `127.0.0.1` IP-адресом контейнера. Отделите сегмент сети датчиков и используйте HTTPS там, где трафик выходит за пределы доверенной LAN. Инструкции и шаблон автоматизации — [docs/home-assistant.md](docs/home-assistant.md).

## Данные, API и безопасность

- `GET /health` — проверка процесса (без авторизации).
- `POST /api/login`, `POST /api/logout` — вход/выход администратора.
- `GET /api/dashboard`, `GET/POST /api/rooms`, `PATCH /api/rooms/{id}`.
- `POST /api/rooms/{id}/pairing` — одноразовый код MAX.
- `GET/POST /api/readings`, `GET /api/export.csv` — журнал/экспорт.
- `POST /api/ingest` — приём от датчиков с заголовком `X-Api-Key`, опциональным `event_id` для защиты от дублей.

Управляющие API требуют сессионного cookie; ingest требует **отдельного** длинного ключа. Максимальная температура для ввода −40…60 °C — защита от ошибочных сообщений, не санитарный норматив. Даты измерений хранятся в UTC; панель показывает локальное время браузера. Экспорт CSV содержит UTF-8 BOM и разделитель `;` для Excel.

При размещении в школе определите ответственных, сроки хранения, порядок резервного копирования и законные основания обработки идентификаторов MAX пользователей. Не добавляйте ФИО в открытые поля и не выкладывайте `.env` / базу в репозиторий. Сейчас система хранит идентификатор пользователя MAX, привязку к кабинету, время и результаты измерений.

Резервная копия на native-установке (SQLite online backup, без остановки службы):

```bash
sudo /opt/termokontur/.venv/bin/python -c 'import sqlite3; a=sqlite3.connect("/var/lib/termokontur/termokontur.sqlite3"); b=sqlite3.connect("/root/termokontur-backup.sqlite3"); a.backup(b); b.close(); a.close()'
```

## Разработка и тесты

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt
export TERMOKONTUR_DB=./data/termokontur.sqlite3
export TERMOKONTUR_ADMIN_PASSWORD="$(python3 -c 'import secrets;print(secrets.token_urlsafe(20))')"
export TERMOKONTUR_SECRET="$(python3 -c 'import secrets;print(secrets.token_urlsafe(48))')"
uvicorn termokontur.app:app --host 127.0.0.1 --port 8092
python -m pytest -q
```
