# Термоконтур

Температура помещений, история измерений и уведомления через MAX. Показания поступают от сотрудников, автономных Wi-Fi-датчиков и Home Assistant. Панель работает на локальном сервере.

## Что умеет

- Показывает температуру, отклонения от нормы и пропуски измерений.
- Строит графики по кабинетам и зданиям, выгружает данные в CSV.
- Принимает показания через панель и бот MAX.
- Напоминает сотрудникам об измерениях и отправляет сообщения.
- Подключает датчики ESP32-C3 по USB, сохраняет их историю и обновляет прошивку.
- Создаёт резервные копии и восстанавливает данные.

Нормы температуры задаются для каждого помещения. По умолчанию показания устаревают через 26 часов. Сбор за сегодня учитывает часовой пояс организации.

Проект проходит испытания. Работа с физическими платами, питание и откат прошивки требуют проверки на стенде. Результаты: [проверки датчиков](docs/sensors/VALIDATION.md), [план внедрения](docs/pilot-checklist.md).

## Установка на Debian в Proxmox

Нужен контейнер Debian 12/13: 1 vCPU, 512 МБ–1 ГБ памяти, диск от 4 ГБ и постоянный IP в локальной сети.

Выполните от `root`:

```bash
apt update && apt install -y git ca-certificates
git clone https://github.com/TeenKode/Termokontur.git
cd Termokontur
bash scripts/install-debian.sh
```

Сохраните пароль администратора: установщик показывает его один раз. Откройте `http://IP-КОНТЕЙНЕРА:8092/` и войдите.

Установщик сохраняет настройки в `/etc/termokontur/termokontur.env`, данные — в `/var/lib/termokontur/`. Повторная установка сохраняет базу и секреты.

Проверка и перезапуск:

```bash
systemctl status termokontur --no-pager
journalctl -u termokontur -n 100 --no-pager
systemctl restart termokontur
```

HTTP используйте только в доверенной сети. Для защищённого подключения настройте HTTPS или VPN. Не открывайте порт 8092 в интернет.

## Первый запуск

1. В **Настройки → Организация** укажите название и часовой пояс.
2. В **Помещения** добавьте кабинеты и нормы температуры. Для списка используйте **Добавить списком**: до 250 кабинетов, в том числе диапазоны `101-125` и строки из Excel.
3. Подключите сотрудников MAX или датчики. Измерение можно добавить вручную.
4. В **Обзор** проверьте первые показания.
5. В **Настройки → Данные и резервные копии** включите копирование и скачайте первую копию.

Отключённые помещения можно восстановить без потери истории. Светлая, тёмная и системная темы доступны в **Настройки → Внешний вид**; выбор сохраняется в браузере.

## Датчики ESP32-C3

Поддерживаются DHT11, DHT22/AM2302, SHT3x, SHT4x, AHT20, BME280 и DS18B20. Одна плата работает с одним модулем; DS18B20 измеряет только температуру.

Для прошивки 0.1.5 или новее:

1. Откройте панель по HTTPS в Chrome или Edge на компьютере.
2. В разделе **Датчики** загрузите **Комплект USB-прошивки** — ZIP из артефакта GitHub Actions `termokontur-sensor-esp32c3`.
3. Нажмите **Прошить и подключить по USB**. Укажите помещение, тип модуля, Wi-Fi 2,4 ГГц и HTTPS-адрес панели.
4. Разомкните SW1, отключите USB зарядки TP4056 и подключите USB SuperMini кабелем с передачей данных.
5. Подтвердите удаление данных новой платы и нажмите **Прошить и настроить**. Доступ выдаётся автоматически.
6. После завершения отключите USB SuperMini и USB зарядки TP4056. Включите питание от аккумулятора и проверьте первые данные в карточке.

USB-прошивка удаляет настройки, ключ и журнал платы. Работающие датчики обновляйте через карточку: загрузите `firmware.bin` и назначьте обновление. Для изменения настроек без стирания используйте **Настроить без прошивки**.

По умолчанию датчик измеряет каждые 30 минут и передаёт данные раз в сутки. Интервалы меняются в карточке. Статус отражает последнее подключение: между передачами датчик спит.

Инструкции: [подключение по USB](docs/sensors/USB-ONBOARDING.md), [настройка с телефона](docs/sensors/SETUP.md), [схемы](docs/sensors/SCHEMATICS.md), [замена модуля](docs/sensors/SENSOR-TYPES.md).

## Экспериментальная поддержка ESP-01S (ESP8266EX, Flash 1 МБ)

Для модулей с Winbond W25Q80 (8 Мбит) добавлена **отдельная** прошивка
[ESP-01S 1 МБ](firmware/esp01s/README.md). Она использует SHT40 на GPIO0/GPIO2,
требует пайки GPIO16 → RST для Deep Sleep, сохраняет измерения во Flash
и передаёт архив в существующий API по HTTPS с индивидуальным ключом.

По умолчанию измерения каждые 30 минут, синхронизация раз в сутки. Для
начальной настройки предусмотрен [скрипт USB–UART](firmware/esp01s/provision.py).
Оригинальная прошивка ESP32-C3 и её USB-мастер **не подходят** для ESP-01S.

Начиная с этой ветки сервер принимает модель `esp01-sht40-v1`; значение
`battery_mv=0` означает, что напряжение аппаратно не измеряется. OTA для
ESP-01S пока запрещено (только USB–UART), а замена аккумулятора/зарядка
требуют аппаратного выключения питания. **Работа на реальной плате и ток
сна пока не проверены**, это экспериментальная реализация.

## Бот MAX

1. Получите токен своего бота MAX.
2. Сохраните его в **Настройки → Бот MAX** и нажмите **Проверить подключение MAX**.
3. Отправьте боту `/start`.
4. В **Помещения → Коды MAX** создайте коды и передайте сотрудникам команды `/bind КОД`.

Бот получает сообщения через Long Polling; публичный IP не нужен. В Debian установщик создаёт службу `termokontur-max`. При проблемах используйте [инструкцию подключения MAX](docs/max-long-polling.md).

Сотрудник выбирает **Отправить за сегодня**, кабинет и температуру. Кнопка **Изменить за сегодня** исправляет показание MAX; первое значение и авторы остаются в истории. Показания датчика и администратора через MAX не меняются.

Команды: `/rooms` — кабинеты, `/today` — показания за сегодня, `/temp 21,5` — температура для одного кабинета, `/temp ID 21,5` — для выбранного, `/unbind ID` — отключение кабинета.

В **Настройки → Уведомления** задайте расписание напоминаний и температурные предупреждения. Там же можно отправить разовое сообщение сотрудникам. [Подробнее об уведомлениях](docs/notifications.md).

## Home Assistant

В **Настройки → Датчики и API** создайте и сохраните ключ. После замены старый ключ сразу перестаёт работать: обновите его во всех интеграциях.

Пример запроса на сервере:

```bash
curl -X POST http://127.0.0.1:8092/api/ingest \
  -H "Content-Type: application/json" \
  -H "X-Api-Key: ВАШ_КЛЮЧ" \
  -d '{"room_id":1,"value":21.8,"device":"sensor.class_101"}'
```

Для запроса с другого устройства замените адрес сервера. За пределами доверенной сети используйте HTTPS. [Настройка Home Assistant](docs/home-assistant.md).

Автономные датчики передают данные в Home Assistant через MQTT. Брокер настраивается в **Датчики → Home Assistant / MQTT**. Передаётся последнее измерение, полная история остаётся в Термоконтуре.

## HTTPS

В **Настройки → HTTPS-сертификат** загрузите сертификат с полной цепочкой и закрытый ключ. Поддерживаются PEM и DER, максимум 256 КБ на файл. Для зашифрованного ключа укажите пароль.

Нажмите **Применить HTTPS (перезапуск)** и откройте `https://АДРЕС-СЕРВЕРА/`. Порт 443 должен быть свободен. Для собственного центра сертификации настройте доверие на устройствах и укажите корневой PEM при подключении датчика.

Если HTTPS обслуживает Nginx или Caddy, настройте внешний прокси и установите `TERMOKONTUR_SECURE_COOKIE=1`. Встроенный HTTPS отдельно включать не требуется.

Сертификат и ключ хранятся отдельно от SQLite. После удаления загруженной пары применяются `TERMOKONTUR_TLS_CERT_FILE`, `TERMOKONTUR_TLS_KEY_FILE` и `TERMOKONTUR_TLS_KEY_PASSWORD`, если они заданы; иначе сервер возвращается к HTTP.

## Резервные копии и обновления

В **Настройки → Данные и резервные копии** можно создать, скачать, загрузить и восстановить копию SQLite до 100 МБ. При восстановлении текущая база заменяется, все сеансы завершаются. Перед заменой создаётся страховочная копия.

Автокопии: интервал 0–30 дней, 0 — выключено; хранение до 100 копий. Срок хранения основного журнала: 0 — бессрочно, иначе 30–3650 дней. Архив автономных датчиков автоматически не очищается.

Копии содержат настройки, токены и идентификаторы MAX. Храните их в защищённом месте на другом устройстве. Отдельно сохраняйте HTTPS-сертификат и ключ.

В **Настройки → Обновление системы** нажмите **Проверить обновления**, затем **Установить обновление**. Автообновление доступно в Debian LXC. Ручное обновление: `git pull`, затем `sudo bash scripts/install-debian.sh`.

## Docker Compose

```bash
cp .env.example .env
# Замените все REPLACE_WITH_... случайными секретами.
docker compose up -d --build
```

Панель: `http://localhost:8092/`, после настройки сертификата — `https://localhost/`. Данные хранятся в томе `app-data`.

Для MAX задайте `MAX_BOT_TOKEN` и выполните:

```bash
docker compose --profile max up -d --build
```

Обновляйте контейнеры через Docker Compose. Для дополнительных центров сертификации добавьте доверенные сертификаты в образ.

## Разработка

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt
export TERMOKONTUR_DB=./data/termokontur.sqlite3
export TERMOKONTUR_ADMIN_PASSWORD="$(python3 -c 'import secrets;print(secrets.token_urlsafe(20))')"
export TERMOKONTUR_SECRET="$(python3 -c 'import secrets;print(secrets.token_urlsafe(48))')"
python -m termokontur.server
python -m pytest -q
```

Основные API: `/health`, `/api/login`, `/api/logout`, `/api/dashboard`, `/api/rooms`, `/api/readings`, `/api/export.csv`, `/api/ingest`. Управление требует сеанса администратора; приём внешних показаний — отдельного ключа. Параметр `event_id` защищает `/api/ingest` от повторных записей.
