# Термоконтур / Termokontur

**Локальная система мониторинга температуры помещений** для школ, детских садов, офисов и других зданий. Бесплатная, открытая, без облачной зависимости для веб-панели. Ручной ввод, MAX-бот и датчики через Home Assistant используют одну базу измерений.

> **Версия 0.1.0 — MVP.** Панель и приём показаний готовы для пробного развёртывания. Интеграция MAX через Long Polling предназначена **только для тестирования** согласно документации MAX; для постоянной эксплуатации необходим переход на Webhook с доверенным HTTPS. Напоминания по расписанию, несколько ролей, полноценные нормативные отчёты и управление датчиками Zigbee пока не реализованы.

## Возможности

- Учёт корпусов, этажей, кабинетов, типов помещений и индивидуальных температурных диапазонов.
- Панель со статусами «в норме», «ниже», «выше», «нет свежих данных». По умолчанию показание считается устаревшим через 26 часов.
- Журнал и график измерений; ручной ввод администратором, экспорт CSV для Excel.
- MAX: одноразовая привязка учителя к кабинету; ввод температуры сообщением.
- Home Assistant: входящий API с отдельным ключом, идемпотентность по `event_id`.
- Вход администратора по паролю, cookie с подписью, проверка источника запросов; отсутствие незаданных паролей по умолчанию.
- SQLite в WAL-режиме. Данные сохраняются после перезагрузки.
- **Установка без Docker** через systemd в Debian 12/13 LXC Proxmox; Docker Compose для желающих.

## Быстрый запуск в Proxmox LXC (без Docker)

Рекомендуемый контейнер: Debian 13, 1 vCPU, 512 МБ–1 ГБ RAM, диск от 4 ГБ, статический IP в школьной сети. Белый IP не требуется.

Внутри контейнера от `root`:

```bash
apt update && apt install -y git ca-certificates
git clone https://github.com/TeenKode/Termokontur.git
cd Termokontur
bash scripts/install-debian.sh
```

Установщик создаёт пользователя `termokontur`, Python venv, настройки в `/etc/termokontur/termokontur.env`, базу в `/var/lib/termokontur/` и службу systemd. При **первой** установке генерирует случайный пароль администратора и печатает его **один раз** в терминал. Сохраните пароль.

Откройте `http://IP-КОНТЕЙНЕРА:8092/` из локальной сети.

```bash
systemctl status termokontur --no-pager
journalctl -u termokontur -n 100 --no-pager
systemctl restart termokontur
```

Повторный запуск установщика сохраняет существующие секреты и базу. Для обновления: `git pull`, затем `sudo bash scripts/install-debian.sh`.

> На локальном HTTP передача пароля не шифруется. Разрешайте доступ только из доверенной школьной сети. Для доступа извне используйте VPN или обратный HTTPS-прокси с доверенным сертификатом. Не публикуйте порт 8092 напрямую в интернет. Для HTTPS установите `TERMOKONTUR_SECURE_COOKIE=1` в конфигурации и перезапустите службу.

## Установка Docker Compose (альтернативная)

```bash
cp .env.example .env
# Замените ВСЕ REPLACE_WITH_... на длинные случайные секреты.
docker compose up -d --build
```

Панель: `http://localhost:8092/`. Данные в volume `app-data`. Для MAX (только тестирование): настройте `MAX_BOT_TOKEN` и запустите `docker compose --profile max up -d --build`.

## Начало работы

1. Войдите в панель под сгенерированным паролем.
2. Откройте **Помещения**, добавьте корпус и кабинеты. Диапазоны по умолчанию 18–24 °C — пример для настройки, **не универсальный норматив**. Установите диапазоны по действующим требованиям для каждого типа помещения.
3. В разделе **Измерения** занесите первые показания.
4. Для MAX нажмите **Код MAX** у кабинета и передайте одноразовый код учителю. Для датчиков используйте API `POST /api/ingest`.

## MAX без публичного IP (экспериментально)

1. Создайте MAX-бота в доступном вам аккаунте MAX для бизнеса (при необходимости требуется верификация организации), получите токен.
2. Откройте конфигурацию: `sudo nano /etc/termokontur/termokontur.env`.
3. Укажите `MAX_BOT_TOKEN=...` — храните токен в секрете.
4. Запустите `sudo systemctl enable --now termokontur-max`.
5. Проверьте `journalctl -u termokontur-max -f`.

**Команды учителя:** `/bind КОД`, `/rooms`, `/temp 21,5` (один кабинет), `/temp 3 21,5` (несколько кабинетов, где 3 — ID), `/unbind 3`, `/help`. Можно отправить просто `21,5`, если кабинет один. Одноразовый код действует 30 минут. Бот принимает данные **только в личном диалоге** и только для привязанных кабинетов.

Связь с MAX — исходящие HTTPS-запросы сервера, поэтому белый IP и проброс портов не требуются. В API MAX необходимо использовать `https://platform-api2.max.ru` и заголовок `Authorization: <bot_token>`. Обновления сохраняют `marker` в SQLite; повторные события не создают дубликатов измерений. **MAX прямо обозначает Long Polling как неподходящий для production**. Для постоянной эксплуатации запланирован Webhook через туннель и публичный доверенный HTTPS, совместимость маршрута нужно проверить отдельно.

Официальные источники: [GET /updates](https://dev.max.ru/docs-api/methods/GET/updates), [POST /messages](https://dev.max.ru/docs-api/methods/POST/messages).

## Home Assistant

В веб-панели узнайте ID нужного помещения. Ключ датчиков автоматически генерируется при установке без Docker и находится в файле `/etc/termokontur/termokontur.env` под именем `TERMOKONTUR_INGEST_KEY`.

Пробный запрос из доверенной сети:

```bash
curl -X POST http://127.0.0.1:8092/api/ingest \
  -H "Content-Type: application/json" \
  -H "X-Api-Key: ВАШ_КЛЮЧ" \
  -d '{"room_id":1,"value":21.8,"device":"sensor.class_101"}'
```

**Важно:** выполняйте эту команду внутри контейнера или замените `127.0.0.1` IP-адресом контейнера. Отделите сегмент сети датчиков и используйте HTTPS там, где трафик выходит за пределы доверенной LAN. Инструкции и шаблон автоматизации — [docs/home-assistant.md](docs/home-assistant.md).

## Данные, API и безопасность

- `GET /health` — проверка процесса (без авторизации).
- `POST /api/login`, `POST /api/logout` — вход/выход администратора.
- `GET /api/dashboard`, `GET/POST /api/rooms`, `PATCH /api/rooms/{id}`.
- `POST /api/rooms/{id}/pairing` — одноразовый код MAX.
- `GET/POST /api/readings`, `GET /api/export.csv` — журнал/экспорт.
- `POST /api/ingest` — приём от датчиков с заголовком `X-Api-Key`, опциональным `event_id` для защиты от дублей.

Управляющие API требуют сессионного cookie; ingest требует **отдельного** длинного ключа. Максимальная температура для ввода −40…60 °C — защита от ошибочных сообщений, не санитарный норматив. Даты измерений хранятся в UTC; панель показывает локальное время браузера. Экспорт CSV содержит UTF-8 BOM и разделитель `;` для Excel.

При размещении в школе определите ответственных, сроки хранения, порядок резервного копирования и законные основания обработки идентификаторов MAX пользователей. Не добавляйте ФИО в открытые поля и не выкладывайте `.env` / базу в репозиторий. Сейчас система хранит идентификатор пользователя MAX, привязку к кабинету, время и результаты измерений.

Резервная копия на native-установке (SQLite online backup, без остановки службы):

```bash
sudo /opt/termokontur/.venv/bin/python -c 'import sqlite3; a=sqlite3.connect("/var/lib/termokontur/termokontur.sqlite3"); b=sqlite3.connect("/root/termokontur-backup.sqlite3"); a.backup(b); b.close(); a.close()'
```

## Разработка и тесты

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt
export TERMOKONTUR_DB=./data/termokontur.sqlite3
export TERMOKONTUR_ADMIN_PASSWORD="$(python3 -c 'import secrets;print(secrets.token_urlsafe(20))')"
export TERMOKONTUR_SECRET="$(python3 -c 'import secrets;print(secrets.token_urlsafe(48))')"
uvicorn termokontur.app:app --host 127.0.0.1 --port 8092
pytest -q
```
