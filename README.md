# Термоконтур

Температура помещений, история измерений и уведомления через MAX. Показания поступают от сотрудников, автономных Wi-Fi-датчиков и Home Assistant. Панель работает на локальном сервере.

## Что умеет

- Показывает температуру, отклонения от нормы и пропуски измерений.
- Строит графики по кабинетам и зданиям, выгружает данные в CSV.
- Принимает показания через панель и бот MAX.
- Напоминает сотрудникам об измерениях и отправляет сообщения.
- Учитывает школьный календарь по корпусам в отчётах и напоминаниях MAX.
- Подключает датчики ESP32-C3 по USB, сохраняет их историю и обновляет прошивку. Температура и влажность доступны в отчётах.
- Создаёт резервные копии и восстанавливает данные.

Нормы температуры задаются для каждого помещения. По умолчанию показания устаревают через 26 часов. Сбор за сегодня учитывает часовой пояс организации.

Проект проходит испытания. Работа с физическими платами, питание и откат прошивки требуют проверки на стенде. Результаты: [проверки датчиков](docs/sensors/VALIDATION.md), [план внедрения](docs/pilot-checklist.md).

## Установка на Debian в Proxmox

Нужен контейнер Debian 12/13: 1 vCPU, 512 МБ–1 ГБ памяти, диск от 4 ГБ и постоянный IP в локальной сети.

Выполните от `root`:

```bash
apt update && apt install -y git ca-certificates
git clone https://github.com/TeenKode/Termokontur.git
cd Termokontur
bash scripts/install-debian.sh
```

Сохраните пароль администратора: установщик показывает его один раз. Откройте `http://IP-КОНТЕЙНЕРА:8092/` и войдите.

Установщик сохраняет настройки в `/etc/termokontur/termokontur.env`, данные — в `/var/lib/termokontur/`. Повторная установка сохраняет базу и секреты.

Проверка и перезапуск:

```bash
systemctl status termokontur --no-pager
journalctl -u termokontur -n 100 --no-pager
systemctl restart termokontur
```

HTTP используйте только в доверенной сети. Для защищённого подключения настройте HTTPS или VPN. Не открывайте порт 8092 в интернет.

## Первый запуск

1. В **Настройки → Организация** укажите название и часовой пояс.
2. В **Помещения** добавьте кабинеты и нормы температуры. Для списка используйте **Добавить списком**: до 250 кабинетов, в том числе диапазоны `101-125` и строки из Excel.
3. Подключите сотрудников MAX или датчики. Измерение можно добавить вручную.
4. В **Обзор** проверьте первые показания.
5. В **Настройки → Данные и резервные копии** включите копирование и скачайте первую копию.

Отключённые помещения можно восстановить без потери истории. Светлая, тёмная и системная темы доступны в **Настройки → Внешний вид**; выбор сохраняется в браузере.

## Датчики ESP32-C3

Поддерживаются DHT11, DHT22/AM2302, SHT3x, SHT4x, AHT20, BME280, BMP280 и DS18B20. Одна плата работает с одним модулем; BMP280 и DS18B20 измеряют только температуру (BMP280 также умеет измерять давление, но проект его не использует).

Панель и прошивки используют один номер релиза из `termokontur/__init__.py`. При первом запуске с новой версией сервер в фоне получает комплект с GitHub и сохраняет его локально. Бинарники становятся доступны в **Датчики → Прошивки**. Если сервер не может скачать комплект, используйте **Скачать ZIP с GitHub** и загрузите ZIP в той же секции. Комплект текущей версии сразу доступен и для USB, и для OTA.

Чтобы прошить новую плату:

1. Откройте панель по HTTPS в Chrome или Edge на компьютере.
2. В разделе **Датчики** нажмите **Прошить и подключить по USB**. Мастер предложит комплект панели. Укажите помещение, тип модуля, Wi-Fi 2,4 ГГц и HTTPS-адрес панели.
3. Разомкните SW1, отключите USB зарядки TP4056 и подключите USB SuperMini кабелем с передачей данных.
4. Подтвердите удаление данных новой платы и нажмите **Прошить и настроить**. Доступ выдаётся автоматически.
5. После завершения отключите USB SuperMini и USB зарядки TP4056. Включите питание от аккумулятора и проверьте первые данные в карточке.

USB-прошивка удаляет настройки, ключ и журнал платы. Для OTA откройте **Обновление прошивки** в карточке датчика, выберите версию из комплекта панели и нажмите **Назначить обновление**. Для изменения настроек используйте **Настроить без прошивки**.

По умолчанию датчик измеряет каждые 30 минут и передаёт данные раз в сутки. Интервалы меняются в карточке. Статус отражает последнее подключение: между передачами датчик спит.

Инструкции: [подключение по USB](docs/sensors/USB-ONBOARDING.md), [настройка с телефона](docs/sensors/SETUP.md), [схемы](docs/sensors/SCHEMATICS.md), [замена модуля](docs/sensors/SENSOR-TYPES.md).

### Отладка по USB

Откройте **Датчики → Прошивки → Отладка прошивки** по HTTPS в Chrome или Edge на компьютере. Подключите ESP32-C3 и прочитайте версию, идентификатор платы и тип датчика. Кнопка **Пробный замер** на прошивке 1.0.0 и новее показывает температуру, влажность и напряжение на этой странице. Журнал последовательного порта можно скачать в TXT.

С прошивкой 1.0.2 или новее кнопка **Показать пароль точки Wi-Fi** считывает имя сети и действующий пароль по USB. Пароль отображается только по нажатию и скрывается при отключении USB. В журнале и файле TXT пароль скрыт.

С версии 1.0.0 для подключения поддерживается ESP32-C3. Ранее подключённые ESP-01S отключаются при обновлении. Их измерения и выгрузка остаются доступны в карточках со статусом **Архив**.

## Бот MAX

1. Получите токен своего бота MAX.
2. Сохраните его в **Настройки → Бот MAX** и нажмите **Проверить подключение MAX**.
3. Отправьте боту `/start`.
4. В **Помещения → Коды MAX** создайте коды и передайте сотрудникам команды `/bind КОД`.

Бот получает сообщения через Long Polling; публичный IP не нужен. В Debian установщик создаёт службу `termokontur-max`. При проблемах используйте [инструкцию подключения MAX](docs/max-long-polling.md).

Сотрудник выбирает **Отправить за сегодня**, кабинет и температуру. Кнопка **Изменить за сегодня** исправляет показание MAX; первое значение и авторы остаются в истории. Показания датчика и администратора через MAX не меняются.

### Отчёты по зданиям, кабинетам и сотрудникам

Во вкладке **Отчёты** выберите начальную и конечную дату (включительно, максимум 366 календарных дней) и здание — либо все здания сразу. Система рассчитывает:

- **Сдачу показаний:** количество проверенных и пропущенных кабинето-дней, охват и конкретные пропуски по датам.
- **Температурный режим:** среднюю, минимальную и максимальную температуру каждого кабинета, дни со среднесуточной температурой за заданными порогами и отдельные отклоняющиеся измерения.
- **Здания:** охват, среднюю температуру и пропуски за период.
- **Сотрудников MAX:** закрепления на даты отчёта, измеренные и пропущенные кабинето-дни, число лично внесённых показаний и дней с вводом.

Если кабинет закреплён за двумя сотрудниками, достаточно одного измерения, чтобы кабинет считался измеренным для обоих. Даты назначений сохраняются с момента обновления до 0.7.0. Для более ранних периодов отчёт показывает известных авторов внесённых показаний.

В **Настройки → Календарь замеров** задайте график корпусов, каникулы и дополнительные рабочие дни. Общие дни недели берутся из настроек напоминаний. Охват считается по активным кабинетам в дни обязательных замеров. Для графиков используются все датированные показания.

Кнопки **Excel** и **PDF** формируют файлы с выбранными фильтрами. Excel включает лист влажности по зданиям и полный список пропусков. PDF содержит печатную сводку и до 100 пропусков. Для генерации PDF на Debian требуется `fonts-dejavu-core` (устанавливается установщиком).

В **Настройки → Доступ по корпусам** администратор может выдать ответственному отдельный логин и пароль для просмотра своего корпуса и выгрузок. При выборе получателя MAX ему отправляются оповещения о пропущенных сеансах связи и низком напряжении датчика. Администратор входит со своим паролем и пустым логином.

В разделе **Автоматические отчёты через MAX** выберите получателя, здание, периодичность и местное время. Ежедневная сводка содержит вчерашние данные, еженедельная — предыдущие семь завершённых дней. Если датчик ещё должен выгрузить данные за период, сводка ждёт завершения передачи или окончания окна связи. Служба проверяет очередь примерно раз в час. Пользователь MAX должен предварительно открыть бота. Расписания можно отключать и удалять. Сводки приходят текстом.

### Назначение кабинетов из панели без кодов

В отдельной вкладке **Сотрудники** показаны все пользователи, которые уже обращались к этому боту. Отображаются имя и фамилия из MAX, @username (если есть), MAX ID, последняя активность и текущие назначения. Сотрудника можно найти по имени, идентификатору или кабинету.

Чтобы назначить кабинеты, выберите **Назначить кабинеты**, отметьте нужные помещения и сохраните. Из раздела «Помещения» к сотрудникам можно перейти кнопкой **Сотрудники MAX**. Изменения применяются сразу, сотрудник увидит новые помещения при следующем обращении к боту. Для назначения нескольких кабинетов одному сотруднику код не нужен; несколько сотрудников могут быть назначены на один кабинет.

**Уведомить сотрудника в MAX** — необязательная галочка при сохранении. Если она включена и добавлены новые кабинеты, сотруднику будет отправлено одно сообщение с их перечнем. Повторное сохранение тех же назначений не рассылает дубли; при удалении привязок такое уведомление не отправляется. Доставка зависит от доступности MAX; при временном сбое сообщение остаётся в очереди.

Если у сотрудника не отображаются имя или фамилия, в разделе «Сотрудники» нажмите **Обновить ФИО**. Панель запросит профиль из MAX для сохранённого личного диалога. Если ID диалога неизвестен, попросите сотрудника снова отправить боту `/start`.

MAX не предоставляет полный список людей, которые только открывали страницу бота. Для появления в списке сотруднику достаточно **нажать «Начать»** или отправить боту сообщение — передавать код подключения не нужно.

Команды: `/rooms` — кабинеты, `/today` — показания за сегодня, `/temp 21,5` — температура для одного кабинета, `/temp ID 21,5` — для выбранного, `/unbind ID` — отключение кабинета.

В **Настройки → Уведомления** задайте расписание напоминаний и температурные предупреждения. Там же можно отправить разовое сообщение сотрудникам. [Подробнее об уведомлениях](docs/notifications.md).

## Home Assistant

В **Настройки → Датчики и API** создайте и сохраните ключ. После замены старый ключ сразу перестаёт работать: обновите его во всех интеграциях.

Пример запроса на сервере:

```bash
curl -X POST http://127.0.0.1:8092/api/ingest \
  -H "Content-Type: application/json" \
  -H "X-Api-Key: ВАШ_КЛЮЧ" \
  -d '{"room_id":1,"value":21.8,"device":"sensor.class_101"}'
```

Для запроса с другого устройства замените адрес сервера. За пределами доверенной сети используйте HTTPS. [Настройка Home Assistant](docs/home-assistant.md).

Автономные датчики передают данные в Home Assistant через MQTT. Брокер настраивается в **Датчики → Home Assistant / MQTT**. Передаётся последнее измерение, полная история остаётся в Термоконтуре.

## HTTPS

В **Настройки → HTTPS-сертификат** загрузите сертификат с полной цепочкой и закрытый ключ. Поддерживаются PEM и DER, максимум 256 КБ на файл. Для зашифрованного ключа укажите пароль.

Нажмите **Применить HTTPS (перезапуск)** и откройте `https://АДРЕС-СЕРВЕРА/`. Порт 443 должен быть свободен. Для собственного центра сертификации настройте доверие на устройствах и укажите корневой PEM при подключении датчика.

Если HTTPS обслуживает Nginx или Caddy, настройте внешний прокси и установите `TERMOKONTUR_SECURE_COOKIE=1`. Встроенный HTTPS отдельно включать не требуется.

Сертификат и ключ хранятся отдельно от SQLite. После удаления загруженной пары применяются `TERMOKONTUR_TLS_CERT_FILE`, `TERMOKONTUR_TLS_KEY_FILE` и `TERMOKONTUR_TLS_KEY_PASSWORD`, если они заданы; иначе сервер возвращается к HTTP.

## Резервные копии и обновления

В **Настройки → Данные и резервные копии** можно создать, скачать, загрузить и восстановить копию SQLite. Загрузки через панель ограничены 1 ГиБ. Перед заменой создаётся страховочная копия, затем завершаются все сеансы.

После восстановления ESP32-C3 с прошивкой 0.7.0 и новее заново отправляет нужные замеры из доступной части журнала. Отсутствующие номера видны в журнале событий датчика. ESP32-C3 с более ранней прошивкой продолжит передачу новых замеров после автоматической фиксации разрыва. Датчики, подключённые после даты резервной копии, нужно снова авторизовать.

Автокопии: интервал 0–30 дней, 0 — выключено; хранение до 100 копий. Срок хранения основного журнала: 0 — бессрочно, иначе 30–3650 дней. Архив автономных датчиков автоматически не очищается.

Копии содержат настройки, токены и идентификаторы MAX. Храните их в защищённом месте на другом устройстве. Отдельно сохраняйте HTTPS-сертификат и ключ.

В **Настройки → Обновление системы** нажмите **Проверить обновления**, затем **Установить обновление**. Автообновление доступно в Debian LXC. Ручное обновление: `git pull`, затем `sudo bash scripts/install-debian.sh`.

При одинаковых зависимостях обновлятор проверяет и копирует установленное Python-окружение. Для новой установки пакетов он использует кеш `/var/lib/termokontur/pip-cache`. Ускорение действует при обновлениях, запущенных обновлятором версии 1.0.2 или новее.

## Docker Compose

```bash
cp .env.example .env
# Замените все REPLACE_WITH_... случайными секретами.
docker compose up -d --build
```

Панель: `http://localhost:8092/`, после настройки сертификата — `https://localhost/`. Данные хранятся в томе `app-data`.

Для MAX задайте `MAX_BOT_TOKEN` и выполните:

```bash
docker compose --profile max up -d --build
```

Обновляйте контейнеры через Docker Compose. Для дополнительных центров сертификации добавьте доверенные сертификаты в образ.

## Разработка

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt
export TERMOKONTUR_DB=./data/termokontur.sqlite3
export TERMOKONTUR_ADMIN_PASSWORD="$(python3 -c 'import secrets;print(secrets.token_urlsafe(20))')"
export TERMOKONTUR_SECRET="$(python3 -c 'import secrets;print(secrets.token_urlsafe(48))')"
python -m termokontur.server
python -m pytest -q
```

Основные API: `/health`, `/api/login`, `/api/logout`, `/api/dashboard`, `/api/rooms`, `/api/readings`, `/api/export.csv`, `/api/ingest`. Управление требует сеанса администратора; приём внешних показаний — отдельного ключа. Параметр `event_id` защищает `/api/ingest` от повторных записей.

### Архитектура

- `termokontur/app.py` собирает приложение FastAPI и управляет задачами обслуживания и MQTT. Маршруты панели распределены по модулям в `termokontur/web/`. Регистрация и синхронизация автономных датчиков находятся в модулях `sensors` и `sensor_onboarding`.
- Панель и отдельный процесс MAX используют одну SQLite-базу в режиме WAL. Оба вызывают `db.initialize()`. Миграции выполняются одной транзакцией и фиксируют версию в `PRAGMA user_version`. Для следующего изменения схемы добавьте шаг в `migrations.py`. Базовая схема для прежних установок хранится в `schema_v1.sql`.
- При восстановлении миграции применяются к временной копии. Успешно обновлённая копия заменяет рабочую базу через SQLite Backup API.
