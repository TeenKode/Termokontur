# Термоконтур — ESP-01S (ESP8266EX, Flash 1 МБ)

**Статус: экспериментальная прошивка, физические испытания не пройдены.**
Плата на фотографии пользователя содержит Winbond 25Q80 (8 Мбит = 1 МиБ).
Этот каталог намеренно не использует бинарники, загрузчик, настройки USB/JTAG
или таблицу разделов ESP32-C3.

## Аппаратная часть

- SHT40 (3,3 В): SDA → GPIO0, SCL → GPIO2; подтяжки 4,7–10 кОм на обеих линиях
  к 3,3 В, только если их нет на модуле. Оба GPIO должны быть HIGH при старте.
- Для пробуждения через 30 минут: **вывод 8 корпуса ESP8266EX, GPIO16/XPD_DCDC,
  соединить с RST**. На колодке ESP-01 GPIO16 отсутствует; требуется микропайка.
  Проверьте ориентацию корпуса и контакты мультиметром перед подключением.
- VCC/EN: стабильные 3,3 В, общий GND. Питание от BL-5C **только через**
  подходящий LDO и защиту батареи; нельзя подавать 4,2 В прямо на ESP.
- Штатная плата ESP-01 **не имеет доступного входа для измерения BL-5C**.
  Передаётся `battery_mv=0` («неизвестно»). Пороги Wi-Fi/OTA по аккумулятору
  к этой аппаратной ревизии неприменимы.
- Во время зарядки устройство необходимо выключать аппаратным SW1. Автоматический
  режим обнаружения зарядки и 30-минутная пауза охлаждения пока **не реализованы**.
  Находясь в питании от зарядного устройства, датчик не должен измерять температуру.
- USB-UART адаптер **3,3 В** с питанием, рассчитанным на пиковые токи ESP8266.
  Для ROM-прошивки GPIO0 удерживается LOW при RESET; для работы GPIO0 HIGH.
  Не соединяйте USB-UART 5 В напрямую с ESP.

## Режим работы

- Измерение SHT40 каждые 1800 секунд, Wi-Fi выключен между передачами.
- После настройки/потери времени выполняется первоначальный защищённый sync.
- Сохранение каждого измерения в LittleFS с CRC32 и seq. При отсутствии Wi-Fi
  записи сохраняются; переполнение **останавливает сбор**, не удаляя архив молча.
- Пакеты до 4 записей, перенос `ack_seq`, идемпотентное повторение.
- UTC берётся только от проверенного HTTPS-сервера. После Deep Sleep учитывается
  время RTC; после холодного перезапуска «неизвестное» измерение не получает
  выдуманную дату. Дрейф RTC требует стендовых проверок.
- OTA **на 1 МБ отключено до аппаратного испытания**: удалённое назначение
  опасно без проверенного резерва памяти, проверки SHA-256 и восстановления.
  Перепрошивка пока только USB-UART. Другие датчики продолжают использовать OTA.
- MAX и Home Assistant/MQTT остаются серверными интеграциями.

## Сборка

```bash
cd firmware/esp01s
python -m pip install platformio==6.1.18
pio run -e esp01s-1mb
```

Время и наличие места под приложение необходимо проверить на реальном образе.
Нельзя прошивать `firmware/sensor/firmware.bin` от ESP32-C3 на ESP8266.

## Настройка по последовательному порту

При пустой конфигурации ESP ждёт команду с UART 115200 бод.
Подключите USB-UART, откройте терминал, отправьте **одну строку** с префиксом
`TKCFG ` и JSON-объектом (PEM содержит экранированные `\\n`):

```json
{"wifi_ssid":"SCHOOL-WIFI","wifi_password":"SECRET","server":"https://monitor.example.ru","ca_pem":"-----BEGIN CERTIFICATE-----\\n...\\n-----END CERTIFICATE-----\\n","trusted_time":1794830400,"device_id":"tk-0123456789abcdef","enroll_code":"ONE-TIME-CODE"}
```

`device_id` и `enroll_code` создайте через административный
`POST /api/sensors/devices`. `ca_pem` должен быть **проверенным офлайн**
корневым/самоподписанным сертификатом TLS узла; непроверенный сертификат с сети
доверенным не становится. `trusted_time` — UNIX-время, полученное на доверенном
компьютере в момент настройки (только для начальной проверки сертификата).

После принятия команды устройство сохраняет конфигурацию, перезапускается,
получает индивидуальный token через `POST /api/sensors/enroll` и сохраняет
его во Flash. Бессрочного общего ключа нет. Не публикуйте serial-логи
с Wi-Fi секретами, кодом и токеном; USB-соединение защищено только физическим
доступом. Рекомендована отдельная школьная Wi-Fi VLAN с доступом к HTTPS панели.

## Известные ограничения

- Нет автоматического USB-мастера/веб-режима настройки, датчика зарядки,
  измерения напряжения батареи и подтверждённого OTA.
- Нужно измерить реальные токи сна, пиковые токи TLS и Wi-Fi, поведение GPIO0/2,
  корректность GPIO16 → RST, CRC SHT40, восстановление после потери питания,
  журнальный fault injection и пределы хранения.
- В отличие от ESP32-C3 нет аппаратного эмулятора прежнего NVS/USB RPC.
- Требуются физические испытания сертификатов с TLS цепочкой школы.
- `/api/sensors/firmware` по-прежнему загружает только ESP32-C3 образ;
  пока ESP-01 обновляется вручную. Сервер блокирует кросс-модельный OTA.
