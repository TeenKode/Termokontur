# Sensor API v1

Префикс `/api/sensors`. Все соединения платы — исходящие HTTPS. Браузерные административные операции используют обычную сессию Термоконтура и проверку Origin. Устройства имеют индивидуальные bearer credentials. Секреты не передаются в URL.

## Регистрация

Администратор создаёт устройство `POST /devices {name, room_id}` и один раз получает `{device_id,code,expires_in}`. Это административное разрешение регистрации конкретного устройства/помещения. Код случайный, индивидуальный, срок 7 суток. В БД хранится SHA-256 кода.

`POST /enroll {device_id,code,hardware_id,model}` → `{token}`. `hardware_id` — 12 строчных hex цифр MAC. `model="c3-sht40-v1"`. Повтор до первого sync разрешён только с той же платой и возвращает тот же token: потеря HTTP-ответа не блокирует настройку. После первого успешного sync bootstrap-код удаляется. Смена аппаратного MAC, токена по общему ключу или саморегистрация неизвестного ID запрещены. Токен хранится на сервере только как SHA-256; исходный token — в NVS платы. Rekey выполняется администратором; архив и seq сохраняются.

## Sync

`POST /devices/{device_id}/sync`, заголовок `Authorization: Bearer <token>`.

```json
{
  "model":"c3-sht40-v1","firmware":"0.1.0",
  "next_seq":2,"lost":0,"rssi":-65,"battery_mv":3910,
  "config_version":1,"boots":48,"ota_failures":0,"ota_generation":0,"error":"",
  "records":[{
    "seq":1,"boot_id":"0123456789abcdef","uptime_s":1800,
    "measured_at":1794700000,"time_quality":"rtc",
    "temperature":21.5,"humidity":45.1,"battery_mv":3910,
    "interval_s":1800,"error":""
  }]
}
```

`next_seq` — первый ещё не выделенный номер; `ack_seq` в ответе — первый ещё не подтверждённый номер. Seq начинается с 1, не сбрасывается при отключении питания, в API ограничен безопасным JSON integer 2^53−1. Отправка не более 100 записей на пакет; прошивка использует 32 для ограничения RAM. Номера возрастают. Первичный ключ — `(device_id,seq)`. Изменившееся содержимое повторного seq вызывает 409 и откат всей транзакции. Идентичный повтор не меняет измерение, время получения и историческую привязку помещения.

Транзакция `BEGIN IMMEDIATE` сохраняет пакет, связанные показания основного журнала, счётчики и очередь MQTT. Ответ ACK формируется только после успешного commit. Несколько плат могут синхронизироваться параллельно; SQLite сериализует запись. HTTP 401 не стирает credentials автоматически: иначе отозванное устройство могло бы бесконечно регистрироваться повторно.

Пропуск seq разрешается только при достаточном монотонном `lost`. Сервер отдельно хранит уже учтённые в ACK пропуски, поэтому полный счётчик потерь можно прислать до передачи всех страниц. Пустой heartbeat никогда не подтверждает неотправленные записи. Неподтверждённый хвост потерь будет учтён при следующей успешно сохранённой записи.

Ответ:

```json
{
  "ack_seq":2,"time":1794700100,
  "config":{"version":1,"measure_s":1800,"send_s":86400,"cool_s":1800,
    "wifi_budget_s":45,"wifi_min_mv":3600,"cutoff_mv":3300,"ota_min_mv":3900,
    "tx_qdbm":34,"adc_scale_ppm":2000000,"enabled":true},
  "ota":null
}
```

`config.version` увеличивается сервером, диапазоны и взаимный порядок порогов проверяются обеими сторонами. Применение на устройстве происходит после записи CRC/versioned NVS blob. При повреждённой конфигурации используются консервативные defaults с диагностикой. При повреждении состояния seq/ACK прошивка сохраняет Flash и останавливает обычную работу; автоматический NVS erase запрещён.

OTA содержит `{id,version,sha256,size,generation}`. Генерация меняется при новом административном назначении, включая повтор того же образа; этим разрешается новая серия из трёх попыток. Бинарник доступен только этому датчику: `GET /devices/{id}/firmware/{firmware_id}` с bearer. Административные endpoints загрузки/назначения требуют сессию; скачивание образа не принимает одну лишь админскую cookie.

## Время

- `unknown`: `measured_at=null`; известны boot_id, последовательность и относительное uptime. Нет скрытого восстановления UTC через `received_at`.
- `sntp`: часы синхронизированы через SNTP. SNTP в этом прототипе не аутентифицирован; использовать доверенную школьную сеть/NTP, криптографически подтверждённое время этим не обещается.
- `server`: время непосредственно от ответа проверенного HTTPS-сервера.
- `rtc`: часы сохранялись между Deep Sleep. Дрейф внешним прецизионным RTC не компенсируется.

При первичной настройке задаётся текущее время телефона. После полной потери питания сохранённый timestamp сервера служит только нижней временной опорой для TLS, а не датой измерения. SNTP запускается до HTTPS и имеет ограниченный бюджет; если доступной опоры недостаточно для проверки актуального сертификата, нужно восстановить NTP или повторить локальную настройку. TLS never-insecure обхода нет. Unknown-записи не получают выдуманные даты после сети; их время остаётся неизвестным.

## Flash

Раздел datalog 0x60000 (384 КиБ), запись 56 байт + CRC32 + commit marker = 64 байта. Номинально 6144 записи / 48 в сутки = **128 суток**. Это максимум при чистом журнале; не гарантированный срок: незавершённые слоты, ошибки, ускоренный интервал уменьшают ёмкость. При заполнении стирается сектор с наиболее старыми записями. Если они не подтверждены, исчезновение учитывается через `missing(ack,next)` и `lost`.

Номер резервируется атомарным NVS commit **до** записи во Flash. Запись становится видна после последнего commit marker и CRC. Ошибки чтения/erase/write возвращаются вызывающему коду, не заменяются успехом. Неудавшаяся запись остаётся в RTC для повтора после Deep Sleep; полный обрыв питания может потерять её содержимое, но пропуск зарезервированного seq будет учтён. Противоречащие дубли в локальном журнале останавливают работу. ACK проверяется только в границах фактически отправленного пакета.

Нет RTC-буфера из 12 измерений: каждое измерение сразу сохраняется во Flash. Это осознанный выбор надёжности первого прототипа; расход записи включается в измеряемый энергобюджет.

## Выбор чувствительного элемента (прошивка 0.1.2)

В enroll и sync передаётся необязательное `sensor_type`: `sht4x` (по умолчанию для старых устройств), `sht3x`, `aht20`, `bme280`, `dht11`, `dht22`, `ds18b20`. Тип sync должен совпадать с регистрацией. Для DS18B20 `humidity` должна быть `null`, для остальных типов обязательна. Записи с ошибкой по-прежнему содержат два `null`. Полный диапазон температуры архива расширен до −55…125 °C. Размер записи Flash и существующие seq/CRC не изменены; отсутствие влажности кодируется `INT32_MIN` в поле humidity. Смена типа разрешена после подтверждения всего журнала и требует повторной регистрации.
