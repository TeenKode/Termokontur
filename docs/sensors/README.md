# Автономный датчик «Термоконтур» — первый прототип

ESP32-C3 SuperMini + SHT40 + BL-5C + TP4056 Type-C с защитой. Измерения каждые 1800 с; передача накопленного пакета каждые 86400 с; оба интервала изменяются в панели. Устройство само обращается к HTTPS-серверу внутри школьной сети или по доступному имени. Публичный IP устройства не нужен.

**Статус:** исходники, программные тесты и сборка описаны в [VALIDATION.md](VALIDATION.md). Физической платы здесь нет; схема является проектом для стенда. Автономность, RF, фактическая точность времени и аппаратный OTA rollback ещё не измерены.

**Начните здесь:** [пошаговое руководство по первой прошивке и настройке](SETUP.md) — Windows/Linux/macOS, браузер и Python, Wi-Fi с телефона, первый обмен, OTA и диагностика.

Комплект для стенда из чистого закоммиченного checkout: установите `platformio==6.1.18 esptool==4.5.1` в Python-окружение и выполните `python scripts/package-sensor.py`. Скрипт собирает и проверяет прошивку, затем создаёт `dist/termokontur-sensor-<версия>-<commit>-bench.zip` с четырьмя образами, скриптом первой записи, инструкциями, manifest и SHA-256. В CI тот же ZIP входит в артефакт `termokontur-sensor-esp32c3`. В панель OTA загружайте только `firmware.bin`.

## Установка панели

Обычное обновление «Термоконтура»: установщик и Docker автоматически берут `requirements.txt`; добавлена зависимость `paho-mqtt`. При запуске выполняется аддитивная миграция `sensor_migrations` (версии 1 и 2). Существующие помещения, показания сотрудников, MAX и старый `/api/ingest` сохраняются. Новая панель появляется в том же приложении, второй сервер не требуется.

Сделайте штатную резервную копию перед обновлением. SQLite backup включает устройства, архив, назначения прошивок и сам бинарный образ. Загруженные прошивки увеличивают размер копии; удаление старых образов через UI пока не реализовано. Автоочистка основного журнала `readings` не удаляет `sensor_records`, чтобы не разрушить проверку повторных seq. Архив датчиков пока сохраняется без автоматического ограничения срока на сервере.

Для датчика нужен HTTPS с полным цепочкой сертификатов и правильным именем. Для собственного CA загрузите его корневой PEM при настройке платы. Проверка сертификата и имени не отключается. Не используйте IP, если сертификат не включает этот IP в SAN. Wi-Fi — 2,4 ГГц, WPA2-Personal либо открытая сеть; Enterprise/802.1X и captive portal не реализованы.

## Первая прошивка

На ПК установите Python и выполните:

```sh
python -m pip install platformio==6.1.18
cd firmware/sensor
pio run
pio run --target upload --upload-port COM5
pio device monitor --port COM5 --baud 115200
```

В Linux вместо `COM5` укажите обнаруженный `/dev/ttyACM0` или другой фактический порт. При необходимости удерживайте BOOT во время подключения USB и отпустите после входа в загрузчик. Не отключайте brownout-детектор. При прошивке внешний плюс питания от TP4056 должен быть разомкнут; подробности в аппаратной инструкции.

Обычный `upload` использует сгенерированные адреса загрузчика, partition table и приложения. Для ручного esptool берите адреса из вывода `pio run -t upload -v`, не угадывайте их. Образ для OTA — только `.pio/build/esp32-c3-supermini/firmware.bin`, не merged flash, не bootloader и не partitions.bin.

## Настройка с телефона

1. В панели откройте «Датчики» → «Подключить датчик», задайте название и действующее помещение. Это разрешение администратора на регистрацию одной платы.
2. Сохраните показанные ID и индивидуальный код. Код действует 7 суток; повторно его не показывают. Общего ключа партии нет.
3. Включите плату без зарядного USB в TP4056. На новой плате открывается защищённая WPA2-точка `Termokontur-XXXX`. Случайный пароль при первом запуске (либо ранее заданный свой) и адрес `http://192.168.4.1` выводятся в USB-монитор. Прочитайте их при первом запуске от USB самой SuperMini, с разомкнутым внешним питанием. Срок режима настройки — 10 минут.
4. Подключите телефон к этой сети. Если Android сообщает «без интернета», сохраните подключение. Откройте адрес вручную: автоматического captive portal нет.
5. Выберите тип чувствительного элемента. Введите SSID/пароль, адрес HTTPS-панели, ID/код, при необходимости CA и школьный NTP. Дата и время телефона передаются в устройство как начальная опора для TLS; перед настройкой проверьте часы телефона.
6. После сохранения плата перезапустится. Если настраивали от USB SuperMini, отключите его и восстановите штатное питание от батареи при отключённом зарядном USB TP4056. При достаточном напряжении плата зарегистрируется и передаст первый пакет. Код окончательно погасится после первого успешного sync.
7. Первое измерение может иметь неизвестную дату: оно сделано до сетевой синхронизации. Оно сохранится в архиве с явным признаком, без подставленной даты. Последующие измерения используют часы RTC.

Для повторной настройки после сброса нажмите и держите BOOT **после запуска** не менее 3 секунд в начале приложения. BOOT, удерживаемая во время аппаратного reset, может отправить ESP в ROM-загрузчик; тогда отпустите её и повторите. При смене реквизитов действующего устройства сначала перевыпустите ключ в панели. Переподключение той же платы сохраняет номера и архив. Для замены платы создайте отдельное устройство: один аппаратный MAC нельзя автоматически заменить чужим. Если NVS платы утрачен и seq восстановить невозможно, отключите её прежнюю регистрацию в панели, создайте новый ID и настройте плату заново. При регистрации того же MAC прежняя отключённая запись освобождается, старый токен отзывается, архив сохраняется. Самостоятельное стирание NVS уничтожит неподтверждённые локальные данные; автоматического стирания в программе нет.

SSID, пароль Wi-Fi, адрес панели, CA и NTP задаются локально. Частота измерений/передачи, охлаждение, пороги питания, мощность радио, коэффициент АЦП и пауза измерений управляются удалённо. Удалённая смена сетевых реквизитов с проверкой и откатом не реализована; для неё используйте локальный режим настройки.

## Использование

Карточка показывает последнее соединение, напряжение, состояние, установленную прошивку, полученную/назначенную версию конфигурации и потери. Спящий датчик не объявляется «онлайн»: статус «Данные получены» означает только недавний успешный обмен. Влажность, ошибки и качество времени доступны в архиве и CSV. График показывает измерения с известными датами; через пропуски линии не соединяются.

Температура с достоверной датой и в существующем диапазоне панели −40…60 °C попадает в основной журнал с источником `ha` и автором `Датчик tk-…`. Используется **время измерения**, поэтому суточная выгрузка заполняет предыдущие дни и среднесуточную статистику. Полный архив датчика допускает диапазон SHT40 до +125 °C. Показания неизвестной даты не участвуют в календарных средних. Исторические записи сохраняют прежнее помещение после перепривязки; новые пакеты относятся к текущему помещению. Перед переносом физического датчика выгрузите накопленный журнал, иначе старый офлайн-пакет будет отнесён к новому помещению.

Зарядка определяется наличием входных 5 В TP4056: пауза действует и после окончания тока заряда, пока кабель подключён. При подключении во время операции программа прекращает работу при ближайшей проверке; блокирующий сетевой вызов может завершаться до установленного таймаута (не более 3 с плюс время системных операций). Это программная пауза, не аппаратный разрыв питания. После отключения — полная настраиваемая выдержка 1800 с, если устройство наблюдало зарядку. После полного выключения история зарядки неизвестна; не начинайте измерения сразу после холодного включения горячего устройства.

## OTA

Загрузите `firmware.bin` с новой версией в разделе датчика и назначьте образ. В бинарнике должны быть правильные ESP32-C3 chip ID, имя `termokontur-sensor`, версия `X.Y.Z`; версия извлекается из образа, а не вводится отдельно. Версии меняйте в `CMakeLists.txt` и `platformio.ini` согласованно.

Обновление разрешается только после подтверждения всего журнала и при напряжении не ниже `ota_min_mv`. Датчик загружает только назначенный образ с того же HTTPS-сервера, без редиректов; сверяет длину, проект, версию и SHA-256. Bootloader проверяет ESP-образ. В сборке включён `CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE=y`. Новая программа подтверждается локальной проверкой АЦП, журнала и датчика, а не обязательной доступностью Wi-Fi. При выключенных измерениях диагностика не требует нового показания SHT40.

Обрыв/неверный SHA до смены boot partition оставляет прежнее приложение. Неподтверждённое приложение откатывается загрузчиком при следующем reset. Если новая версия впервые стартует при зарядке/недостаточном питании и уходит спать до подтверждения, возможен консервативный откат. Счётчик попыток хранится до загрузки; после 3 неудач новые предложения блокируются. После устранения причины повторное назначение образа в панели создаёт новую генерацию попыток; устройство сбросит локальный счётчик, когда получит это назначение. Практический тест аварийного образа обязателен до массовой установки.

TLS + административное назначение + SHA защищают передачу и целостность относительно доверенного сервера. Криптографическая подпись образа, Secure Boot, anti-rollback eFuse и шифрование Flash в этом прототипе **не включены**. Физический доступ к плате позволяет извлечь сетевые реквизиты; проект не обещает защиту от такого доступа.

## Home Assistant

В «Датчики» → «Home Assistant / MQTT» задайте свой брокер, логин/пароль и TLS. Пароль при чтении API не раскрывается; пустое поле сохраняет старый. Очередь хранится в SQLite, отправка с QoS 1 и retain выполняется отдельно от приёма показаний. Ошибка брокера не отменяет ACK датчику. Повторная доставка не теряет более новую генерацию состояния.

Discovery создаёт температуру, влажность, напряжение и RSSI. Процент заряда не вычисляется по выдуманной кривой BL-5C. MQTT передаёт последнее состояние раз в сутки; полноценная история каждые 30 минут находится в Термоконтуре. Retained availability означает актуальность последнего обмена, а не физическую доступность спящего устройства. При остановке самого сервера обнаружение его недоступности через отдельный постоянный LWT пока не реализовано.

Официальная документация: [ESP-IDF OTA](https://docs.espressif.com/projects/esp-idf/en/v5.3/esp32c3/api-reference/system/ota.html), [MQTT Discovery](https://www.home-assistant.io/integrations/mqtt/#mqtt-discovery).

## Другие датчики

Начиная с прошивки 0.1.2 доступны DHT11/DHT22, SHT3x/SHT4x, AHT20, BME280 и DS18B20. Выбор в настройке с телефона, соединения и порядок замены: [SENSOR-TYPES.md](SENSOR-TYPES.md).

## Собственный пароль точки настройки

С прошивки 0.1.3 в локальной форме можно задать пароль сети `Termokontur-…` (8–63 печатных ASCII-символа) и подтверждение. Он применяется при следующем входе, хранится в NVS и сохраняется после OTA. Пустые поля сохраняют прежний режим; флажок случайного пароля удаляет собственный и возвращает генерацию при каждом запуске. Первый вход на новую плату — по случайному паролю из USB-монитора. Это отдельный пароль, не пароль рабочей Wi-Fi сети и не пароль администратора панели. Подробнее: [SETUP.md](SETUP.md#задать-свой-пароль-точки-настройки).
