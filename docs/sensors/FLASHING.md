# Прошивка через браузер

**Рекомендуемый способ для 0.1.4+: [прошивка на сайте и автоматическая авторизация по USB](USB-ONBOARDING.md).**

Полная последовательность от новой платы до первого измерения: [SETUP.md](SETUP.md).

## Готовый единый образ

В стендовом ZIP находятся два разных образа:

| Файл | Как использовать |
|---|---|
| `factory.bin` | Первая установка на ESP32-C3, один файл по адресу **0x0**, DIO / 80 MHz / 4 MB |
| `firmware.bin` | Только приложение для существующего механизма OTA Термоконтура |

`factory.bin` собран официальным esptool merge_bin из bootloader, partitions, ota_data_initial и приложения. Промежутки заполнены 0xFF: **запись уничтожает NVS (Wi-Fi, токен, состояние seq)**. Это не способ сохранить настройки или неподтверждённый архив существующего датчика. Даже без Erase all область NVS перезаписывается. Старый datalog за пределами образа может сохраниться: не переиспользуйте такую плату как новый датчик без отдельной процедуры очистки и резервного копирования. Не загружайте factory.bin в панель OTA.

Образ не содержит ключей, SSID или общего кода подключения; после установки выполняется индивидуальная настройка по README. Improv Wi-Fi в прошивке не реализован: кнопка браузерного флешера не заменяет настройку через защищённую точку датчика.

## Прошить сейчас без Python

1. Распакуйте стендовый ZIP, сверьте SHA256SUMS при наличии инструмента проверки. Отсоедините внешний плюс TP4056 перемычкой SW1, затем подключите USB **SuperMini** кабелем с данными. Закройте другие последовательные мониторы.
2. Откройте [официальный ESP Tool](https://espressif.github.io/esptool-js/) в настольном Chrome или Edge с Web Serial. Нажмите Connect и выберите последовательный USB-порт ESP32-C3. При необходимости используйте BOOT/RESET по инструкции платы.
3. Добавьте **одну строку**: адрес `0x0`, файл `factory.bin`. Выберите DIO, 80m, 4MB; начинайте с 115200 baud. Erase all оставьте выключенным: он удаляет также остальной архив Flash.
4. Запустите Program и дождитесь завершения/проверки записи. При ошибке не считайте устройство прошитым; сохраните лог без секретов. После записи перезапустите устройство и откройте монитор 115200 для получения реквизитов точки настройки.
5. Настройте по README. Перед возвратом питания от батареи отключите USB SuperMini. Факт USB-прошивки и запуск на физической плате должны быть отмечены в BENCH.md; здесь они ещё не испытаны.

При отсутствии Web Serial/доступа к порту используйте `flash-sensor.py` и четыре отдельных файла из комплекта. Мобильные браузеры и iOS не являются базовым поддерживаемым сценарием стенда; поддержку проверяйте по наличию `navigator.serial`, а не названию браузера.

## Выбор библиотеки и WASM

Проверено по первичным источникам 15 ноября 2026:

- [Espressif esptool-js](https://github.com/espressif/esptool-js): JavaScript-реализация протокола, Web Serial, ESP32-C3, запись образов и проверка Flash; готовый интерфейс по ссылке выше. Подходит для собственного интерфейса с прогрессом и журналом.
- [ESP Web Tools](https://esphome.github.io/esp-web-tools/): готовый web component с manifest и выбором прошивки по семейству чипа. Альтернативный готовый интерфейс; в текущей панели используется собственный мастер на esptool-js.
- [ESP Lab](https://esplab.mutexpass.com/) заявляет обработку образов через WebAssembly и Web Serial. Пригодность его кода для встраивания, лицензия и реализация WASM не проверены. Готовую проверенную WASM-библиотеку для нашего сценария по этому поиску не выбрали.

WASM сам по себе не даёт доступ к USB: всё равно нужен браузерный транспорт и разрешение пользователя. Для нашей прошивки необходимости в WASM нет; библиотека JS уже решает задачу. Поддержка определяется браузером и ОС. [Документация Web Serial](https://developer.mozilla.org/en-US/docs/Web/API/Web_Serial_API) описывает требования безопасного контекста и разрешений.

## Встроенный мастер Термоконтура

Реализован локальный esptool-js 0.5.7 с зафиксированными зависимостями,
без CDN. Администратор загружает общий стендовый ZIP; API выдаёт неизменяемый
образ по ID под действующей сессией. Мастер проверяет SHA-256, чип/Flash/MAC,
стирает новую плату, записывает образ с MD5 и переключается на USB RPC.

USB RPC получает открытый ключ платы и подпись одноразового запроса. Сервер
сразу разрешает этот ключ и привязывает его к комнате; Wi-Fi и параметры
сохраняются через USB. Полный порядок и ограничения — [USB-ONBOARDING.md](USB-ONBOARDING.md).

Тесты браузера используют имитацию ROM/USB; физический цикл записи ещё не
подтверждён. Сборка/проверка образов выполняется `scripts/package-sensor.py`.
