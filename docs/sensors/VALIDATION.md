## Проверка интерфейса

Дополнительно успешно выполнен `tests/sensors-dom-smoke.cjs` с jsdom 26.1.0 и настоящим временным API-сервером: вход, создание устройства, индивидуальный код, регистрация, приём, детализация, безопасное отображение текста, очередь конфигурации и переключение темы. Это DOM/API-проверка, **без проверки отрисовки и размеров**.

## Проверка браузера

`tests/sensors-browser-smoke.py` запускает изолированный временный сервер и тестирует вход, создание устройства, регистрацию, 48 показаний, доставку конфигурации, ширины 1440/390, светлую/тёмную тему, ошибки JS и горизонтальный overflow. Данные в этом сценарии **синтетические тестовые**, не замеры устройства.

Локальный запуск блокируется окружением: Chromium не может создать Unix socket для ProcessSingleton, скачивание отдельного Playwright-браузера возвращает неполный архив. Общий браузер не видит localhost процесса проверки. Это не считается успешной визуальной проверкой. В GitHub Actions добавлена отдельная browser job со скриншотами; её фактический результат смотреть в PR. Не объявлять UI проверенным до успешного запуска.

## Что проверяют серверные тесты

Административная авторизация; отсутствие общего enroll-ключа; повтор регистрации с потерянным ответом; привязка одной аппаратной платы; погашение bootstrap-кода; индивидуальный bearer; отключение/перевыпуск; идемпотентный повтор; конфликт содержимого seq; атомарный откат пакета; даты из будущего; unknown timestamp без подмены; потерянные номера между страницами; heartbeat без фиктивного ACK; диапазоны/конфигурация; одновременные повторы; назначения OTA/поколения повторов/права скачивания; MQTT Discovery, скрытие пароля, очередь при сбое брокера и сохранение одновременной новой генерации.

## Только на физическом прототипе

- Маркировка и фактические параметры LDO; соответствие разводки SuperMini/TP4056.
- Осциллограммы при Wi-Fi TX, запуске TLS, Flash erase/write и OTA на всех напряжениях.
- Ток сна всей сборки и влияние светодиодов, ёмкости, делителя и драйвера GPIO.
- Полезная ёмкость/саморазряд BL-5C; реальные сроки автономности.
- Температурная погрешность сборки, нагрев зарядки, достаточность 30 минут охлаждения.
- Уровни USB_DET, отсутствие внешней подпитки в OFF, пробуждение по обоим уровням.
- SHT40 адрес/CRC на заказанном модуле, ADC leakage/калибровка.
- Реальный старт после USB, удержание BOOT и повторная локальная настройка.
- 3–5 суток без Wi-Fi с последующей выгрузкой; внезапное отключение питания и корректный учёт потерь.
- OTA: новая рабочая версия, обрыв передачи, неправильный SHA, низкий заряд, подключение зарядки, аварийная новая версия и подтверждённый загрузчиком откат.
- Дрейф RTC и восстановление TLS при отключённом NTP/полной потере питания.
- Устойчивость по памяти и длительности TLS/OTA на реальном MCU, а не только размер статической RAM в отчёте linker.

Включённая опция rollback и успешная компиляция **не означают**, что аварийный откат уже испытан на плате.

## Публикация

Исходники подготовлены в ветке `feat/autonomous-sensors`; есть переносимый патч к базовому main и архив с бинарниками. После явного подтверждения пользователя ветка публикуется в публичном `TeenKode/Termokontur` через PR. Фактические результаты GitHub Actions относятся к точному head SHA PR; локальные проверки выше не заменяют CI. Аппаратные испытания остаются обязательными.
