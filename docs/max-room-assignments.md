# Управление привязками MAX и кодами подключения

В разделе **Помещения** таблица показывает все привязанные к кабинету профили MAX.
Для каждого профиля выводятся имя и фамилия из событий API MAX, публичный
никнейм (если он есть) и неизменный ID. При отсутствии имени отображается
`MAX ID …`. Фамилия и никнейм в MAX могут отсутствовать. Старые привязки
сохраняются: отображаемое имя появится после следующего обращения пользователя
к боту (`bot_started`, личного сообщения или нажатия кнопки). Синхронизация
не требует публичного IP и работает при Long Polling.

Администратор нажимает **Отвязать** рядом с нужным пользователем и подтверждает
действие. Удаляется **только связь выбранного пользователя с выбранным кабинетом**.
История измерений и другие привязки сохраняются. Повторная привязка возможна
через новый одноразовый код. API для этого действия доступен только
авторизованному администратору.

В окне **Коды MAX** доступны две операции:

1. Выбор помещений для новой выдачи: по умолчанию отображаются только кабинеты
   без пользователей MAX и без действующего кода. Можно искать, фильтровать по
   корпусу, выбирать все показанные помещения и менять срок действия (от
   30 минут до 7 дней). За один выпуск — не более 250 кабинетов.
2. Управление действующими неиспользованными кодами: список помещений и сроков
   действия, а также кнопка **Отозвать**. Просмотр самого секретного кода
   после закрытия окна невозможен. Если требуется заменить код, выдайте новый:
   прежний код выбранного помещения будет отозван.

После нажатия **Создать коды** в текущем окне отображаются новые значения,
команды `/bind КОД`, копирование отдельных команд/всех команд и скачивание CSV.
**Обязательно сохраните коды до закрытия окна.** На сервере сохраняется только
SHA-256-хеш кода, не открытый секрет. Выдача кодов не отвязывает уже
подключённых сотрудников. Коды одноразовые.

Серверные маршруты (только для администраторов):

- `GET /api/rooms` — поле `max_users` для каждого помещения.
- `DELETE /api/rooms/{room_id}/max-bindings/{user_id}` — удалить связь.
- `GET /api/max/pairing-codes` — метаданные действующих кодов (без секретов).
- `POST /api/max/pairing-codes` — выдать коды в JSON для однократного
  отображения/экспорта; `POST /api/max/pairing-codes.csv` сохранён.
- `DELETE /api/rooms/{room_id}/pairing` — отозвать ещё не использованный код.

Новые данные профилей автоматически мигрируются при запуске через создание
таблицы `max_users`. В интерфейсе текстовые поля MAX выводятся как текст,
без интерпретации HTML. API помещений защищён авторизацией; коды не хранятся
в открытом виде. Для новой установки не требуется отдельная миграция.


## Общие ежедневные показания для нескольких сотрудников

К одному помещению можно привязать нескольких пользователей MAX. Каждый видит
один и тот же актуальный результат за текущие местные сутки. В кнопочном списке
кабинетов отображаются корпус, номер и статус «Не сдано» или температура.

- **Первый замер MAX:** любой из привязанных сотрудников отправляет температуру.
  Запись создаётся одна на весь кабинет, а не по одной на каждого сотрудника.
- **Повторная попытка:** если другой сотрудник нажал «Отправить за сегодня»,
  бот показывает существующую температуру и предлагает её исправить. Одновременные
  отправки защищены транзакцией SQLite и не дублируют ежедневный MAX-замер.
- **Исправление:** любой *сейчас привязанный* сотрудник может исправить замер MAX
  другого сотрудника. Исходный автор остаётся в `readings.reporter`;
  `max_reading_corrections` фиксирует автора, старое и новое значения и время.
  Повторное получение события MAX не создаёт повторную правку.
- **Журнал:** в панели «Измерения» отображаются первоначальный автор и кнопка
  «История» с последовательностью исправлений. API:
  `GET /api/readings/{reading_id}/corrections` (только администратор).
- **Напоминания:** пока за сутки не получено ни одного показания, напоминание
  придёт каждому привязанному сотруднику (один раз в день согласно расписанию).
  При наличии замера — независимо от автора и источника — напоминаний нет.
  Перед отправкой бот повторно проверяет статус кабинета.
- **Предупреждения:** при отклонении **автоматического датчика** от допустимых
  значений MAX отправляет push всем привязанным пользователям при включённых
  температурных уведомлениях. При ручном вводе бот сразу предупреждает
  отправителя в ответе, чтобы не создавать массовые повторяющиеся оповещения.

Если актуальное показание пришло от Home Assistant или администратора, оно
отображается как уже сданное, но изменять его через MAX нельзя: исходные
измерения датчиков и записи администратора должны оставаться независимыми.
Исторические измерения, сделанные до обновления, сохраняются без удаления.
