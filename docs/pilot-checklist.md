# Пилотное внедрение Термоконтура в школе (Debian 13 / Proxmox LXC)

> Это **план испытаний**, а не подтверждение испытаний на оборудовании организации.
> Отмечайте пункты только по фактически полученным результатам. Не используйте
> рабочие пароли, токены и персональные данные в отчётах или GitHub Issues.

## 1. Предварительная подготовка

- [ ] Выделен отдельный Debian 13 LXC (рекомендуемый начальный минимум: 1 vCPU,
  512 МБ–1 ГБ RAM, диск от 4 ГБ, статический адрес LAN).
- [ ] Создан снимок/backup LXC на Proxmox, назначен ответственный за восстановление.
- [ ] Открыт только локальный порт 8092 для доверенной LAN/VPN; доступ с интернета
  к веб-панели закрыт. Для авторизации через недоверенную сеть настроен доверенный HTTPS.
- [ ] Назначены **три пилотных помещения** с разными условиями: обычный кабинет,
  учебное помещение другого корпуса/этажа и кабинет с датчиком.
- [ ] Для каждого помещения вручную установлены допустимые температурные границы
  по применимым требованиям. Значения 18–24 °C в шаблоне **не являются универсальной нормой**.
- [ ] Настроен часовой пояс `Asia/Vladivostok`, уточнён график напоминаний.
- [ ] Согласован порядок доступа к сведениям о сотрудниках и срокам хранения.

## 2. Чистая нативная установка без Docker

В **новом тестовом** LXC от root:

```bash
apt update && apt install -y git ca-certificates
git clone https://github.com/TeenKode/Termokontur.git
cd Termokontur
bash scripts/install-debian.sh
systemctl is-active termokontur termokontur-max termokontur-update.path
curl -fsS http://127.0.0.1:8092/health
journalctl -u termokontur -u termokontur-max -n 80 --no-pager
```

- [ ] Установщик завершён без ошибки; сохранён **однократно показанный** пароль.
- [ ] Панель открывается по `http://IP-LXC:8092` из LAN, снаружи недоступна.
- [ ] После первого входа пароль изменён; старый пароль и старая сессия недействительны.
- [ ] Созданы три помещения; проверен быстрый массовый ввод номеров,
  отсутствие дублей и восстановление отключённого кабинета.
- [ ] Показания 17,5 / 21,5 / 25,0 °C дают ожидаемые статусы при порогах 18–24 °C.
- [ ] Проверены ежедневная сводка, история и CSV с кириллицей в Excel.
- [ ] После перезагрузки LXC все службы стартуют, показания и настройки сохранены.

## 3. MAX через NAT: проверка реальной доставки

**Обычный домашний/школьный NAT без публичного IP сам по себе не обеспечивает
входящие HTTPS webhook.** Для production необходим внешний доступный HTTPS
endpoint на 443: например, доверенный туннель или VPS с обратным прокси.
Туннель должен публиковать **только** путь `/api/max/webhook`, а не веб-панель.

Поток: `MAX → HTTPS:443 (публичный домен) → туннель/прокси → LXC:8092/api/max/webhook`.
Передавайте заголовок `X-Max-Bot-Api-Secret` без изменений. Внешний TLS-сертификат
должен быть доверенным и действующим, не самоподписанным. Включите надёжный
автозапуск/восстановление туннеля после перезагрузки.

В панели в разделе **Настройки → Интеграции MAX** задайте токен,
зарегистрируйте URL webhook и нажмите **Проверить подключение MAX**.
По документации MAX, если webhook недоступен в течение 8 часов, платформа
может автоматически отменить подписку; в таком случае восстановите
туннель и зарегистрируйте webhook заново.

- [ ] По кнопке диагностики: webhook зарегистрирован, очередь без ошибок.
- [ ] Созданы разовые коды для трёх помещений, CSV передан адресатам отдельно.
- [ ] Каждый тестовый сотрудник выполнил `/bind КОД`.
- [ ] Повторное использование одного кода другим пользователем отклоняется.
- [ ] `/rooms`, `/today`, `/temp 21,5`, `/temp ID 21,5`, `/unbind ID`
  возвращают ожидаемые результаты.
- [ ] Срабатывает оповещение о выходе температуры за диапазон,
  а при возвращении в норму прекращаются повторы отклонения.
- [ ] Кратковременно нарушен **тестовый** канал связи (без отключения службы в
  рабочее время), восстановлена сеть, накопившиеся ответы доставлены.
- [ ] В панели число неотправленных ответов снова равно 0; проверен журнал
  `journalctl -u termokontur-max -n 100 --no-pager`.
- [ ] Неверный webhook-secret даёт HTTP 403; запрос более 64 КиБ даёт HTTP 413.
  Проверять на тестовом endpoint, не раскрывая секрет в истории команд.

**Важно:** диагностика подтверждает наличие подписки у MAX, но не заменяет
фактическую отправку сообщения. Режим Long Polling — только для тестирования.

## 4. Home Assistant / Wi-Fi / Zigbee

Используйте инструкцию [home-assistant.md](home-assistant.md).
Настройте источник и ключ приёма из панели, затем в тестовой LAN проверьте
отрицательные и положительные сценарии:

- [ ] Без `X-Api-Key` и с неверным ключом `POST /api/ingest` отклоняется.
- [ ] С корректным ключом измерение сохраняется в нужном помещении.
- [ ] Повтор события с тем же `room_id`, `device` и `event_id`
  не создаёт дубликат; для разных датчиков одинаковый `event_id` допустим.
- [ ] Отключённый кабинет не принимает измерение.
- [ ] После замены ключа старый перестаёт действовать, новый обновлён в HA.
- [ ] Проверены отключение/обрыв связи с датчиком и переход показания в статус
  «нет свежих данных» после настроенного интервала.

## 5. Резервная копия, обновление и восстановление

Все разрушительные операции выполняйте **только на копии LXC**.
Никогда не имитируйте поломку и не проверяйте откат на рабочем сервере
с реальными измерениями.

- [ ] Создана резервная копия через панель, файл скачан в защищённое хранилище.
- [ ] Проверено автоматическое создание копии, ограничение количества
  автоматических копий и сохранность ручных.
- [ ] На **тестовом клоне** изменены показания, восстановлена предыдущая копия:
  старые данные вернулись, новые пропали, сессия администратора отозвана.
- [ ] На тестовом клоне загружен повреждённый/посторонний SQLite-файл —
  импорт отклонён без потери действующей базы.
- [ ] Установлено обновление через панель; сохранены комнаты, история,
  пароль и настройки MAX/HA.
- [ ] Проверены `systemctl status termokontur-update.path` и
  `journalctl -u termokontur-update.service -n 150 --no-pager`.
- [ ] Откат при ошибочном обновлении проверен в **изолированном CI/клоне**,
  а не внедрением поломанной сборки на рабочем сервере.
- [ ] Восстановлена работоспособность после перезагрузки LXC и после
  восстановления снимка Proxmox.

## 6. Завершение пилота

Фиксируйте для каждого шага **дату, стенд, ожидаемое/фактическое поведение,
результат (успешно/неуспешно) и ссылку на лог без секретов**.

К массовому развёртыванию переходите только после успешного пилота:
работают перезагрузка, создание и восстановление резервных копий,
сообщения MAX, ввод от HA, восстановление туннеля и обновление.
При сбоях в доставке MAX сначала устраните причину и повторите контрольную
отправку. Мониторинг доступности туннеля вне Термоконтура — отдельная
эксплуатационная задача.
